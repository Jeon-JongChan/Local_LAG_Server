2. 데이터 흐름 (인제스트) — 단계별
================================================================================

2.1 PDF 탐색
  - 함수: pdf_parser.discover_pdf_files(DOCS_DIR)
  - data/docs 이하 *.pdf 재귀 수집
  - 이름이 '.'으로 시작하는 파일 제외
  - 상대 경로 키: DOCS_DIR 기준 posix 경로 (예: reports/2024/foo.pdf)

2.2 인제스트 플랜 (ingest._plan_ingest)
  - reset=True        → mode=full, 모든 PDF 대상
  - 인덱스 비어 있음   → mode=full
  - manifest == 현재  → mode=skip (변경 없음)
  - 파일 삭제/크기·mtime 변경 → mode=full
  - 신규 파일만 추가   → mode=append (신규 PDF만 parse)

  ※ local-rag.bat ingest 는 항상 --reset 이므로 full만 사용됨.
  ※ append 모드에서도 FAISS는 삭제 없이 add만 수행 (변경 파일은 full 필요).

2.3 OpenDataLoader 변환
  - 함수: pdf_parser.parse_pdfs_batch(pdf_paths)
  - opendataloader_pdf.convert() 한 번에 여러 PDF (JVM 기동 1회)
  - 출력: data/parsed/ 아래 임시 디렉터리 (배치 후 자동 삭제)
  - OPENDATALOADER_FORMAT 기본값 "json"
  - JSON 파일명: {pdf_stem}.json
  - 헤더 검증·파싱 실패 PDF → data/rejected/ 격리 (+ .reason.txt)

2.4 JSON → 요소 추출
  - _iter_elements(): kids 트리 재귀 순회
  - 처리 타입: paragraph, heading, list, list_item, caption, footnote, table
  - page: "page number" | "page_number" | "pageNumber" | "page"
  - bbox: "bounding box" | "bounding_box" | "bbox" → [left, bottom, right, top]
  - table: rows/kids에서 셀 텍스트를 " | " 로 결합

2.5 청크화 (chunker.elements_to_chunks)
  - 버퍼에 요소 텍스트 누적
  - len(buffer) >= CHUNK_MIN_CHARS(200) 이면 flush
  - 후보 길이 > CHUNK_MAX_CHARS(800) 이면 먼저 flush 후 새 버퍼
  - flush 시 CHUNK_MAX_CHARS 초과분은 CHUNK_OVERLAP_CHARS(80) 겹침으로 분할
  - 메타: file_name, source_path, element_type, page(복수 시 pages), bbox(복수 시 bboxes)

2.6 임베딩
  - models.embed_texts(texts)
  - SentenceTransformer — data/models/embeddings/bge-m3/ 로컬 경로만 로드
  - normalize_embeddings=True → IndexFlatIP와 코사인 유사도 동치
  - bge-m3 출력 차원: 1024
  - 모델 미존재 시 ensure_ml_models.py / local-rag.bat models 로 사전 다운로드 필요

2.7 저장 (store.add_chunks)
  - SQLite id: 기존 count()부터 순차 할당 (0, 1, 2, ...)
  - FAISS add 순서 = SQLite id와 동일 인덱스
  - faiss.index, meta.json 디스크 저장
  - ingest_manifest: rel_path → (size, mtime) 갱신

3. 데이터 흐름 (질의) — 단계별
================================================================================

3.1 전처리
  - ask_question(question, think_mode="auto", history=None)
  - 공백 strip, 빈 문자열 거부
  - store.count()==0 이면 안내 메시지 반환
  - history: ChatStore 메시지 목록 (웹 세션) 또는 없음 (CLI)

3.2 임베딩 질의문
  - _embed_query_text: 질문이 짧고(≤80자) history가 있으면 직전 user 질문과 합침
  - resolve_think_mode: /think · /no_think 인라인 지시어 파싱

3.3 1차 검색 (FAISS)
  - embed_query(embed_text) → shape (1024,)
  - store.search(query_vector, FAISS_TOP_K=20)
  - IndexFlatIP.search → (scores, ids)
  - 각 id로 SQLite chunks 행 조회
  - 반환 dict: id, score, text, file_name, source_path, page, bbox, element_type

3.4 리랭킹
  - models.rerank(question, candidates, RERANK_TOP_K=4)
  - CrossEncoder — data/models/reranker/bge-reranker-v2-m3/ 로컬 경로만
  - (query, chunk_text) 쌍별 score → 내림차순 상위 4개
  - rerank_score 필드 추가

3.5 컨텍스트 조립
  - _build_context(hits):
      [문서 i] {file_name · p.N · bbox=[...]}
      {chunk text}
  - ref_text: "- {citation}" 목록 (답변 하단 [참고 문서])

3.6 LLM 호출
  - llm.chat_answer(question, context, think_mode=..., history=...)
  - POST {LLAMA_CPP_BASE_URL}/chat/completions
  - system: /think 또는 /no_think + 문맥 내 답변·추측 금지
  - messages: system + (선택) history + user([문맥]+[질문])
  - temperature=CHAT_TEMPERATURE
  - max_tokens: instant → LLAMA_NUM_PREDICT(2048), think → LLAMA_NUM_PREDICT_THINK(8192)
  - think_mode:
      instant — 항상 /no_think
      think   — 항상 /think
      auto    — 긴 질문·키워드·복수 물음표 → think, 아니면 instant
  - 실패 시: 검색된 [참고 문서]만이라도 반환

3.7 최종 출력 형식
  {LLM 답변}

  [참고 문서]
  - file.pdf · p.3 · bbox=[72.0, 450.0, 500.0, 480.0]
  - ...

4. 모듈별 상세
================================================================================

4.1 app/settings.py
  - 모든 경로·상수의 단일 출처
  - BASE_DIR = app/ 의 부모 (프로젝트 루트)
  - DATA_DIR, DOCS_DIR, REJECTED_DIR, INDEX_DIR, PARSED_DIR
  - MODELS_DIR: chat / embeddings / reranker
  - SQLITE_PATH, FAISS_PATH, INDEX_META_PATH

4.2 app/pdf_parser.py
  - parse_pdf(): 단일 PDF (개별 work_dir under PARSED_DIR)
  - parse_pdfs_batch(): 배치 (권장, ingest에서 사용)
  - clear_parsed_cache(): full ingest 시 PARSED_DIR 삭제 후 재생성
  - quarantine: 실패 PDF → REJECTED_DIR

4.3 app/chunker.py
  - format_citation(meta): 출처 한 줄 문자열
  - 요소 단위가 아닌 문자 수 기반 청킹 (한국어 RAG 일반 설정)

4.4 app/store.py — VectorStore
  - 싱글 프로세스 전제 (동시 쓰기 락 없음)
  - reset(): chunks·manifest DELETE, faiss.index·meta.json 삭제
  - search(): FAISS id → SQLite 1:1 조회 (벡터 본문은 SQLite에만 존재)
  - 트랜잭션: add_chunks 시 SQLite insert + FAISS add 원자적 commit
  - ※ chat_* 테이블은 reset 대상이 아님 (동일 DB 파일 공유)

4.5 app/models.py
  - 싱글톤 lazy load (_embedder, _reranker)
  - 로컬 경로만 로드 (Hugging Face 자동 다운로드 없음)
  - EMBED_DEVICE: auto → torch.cuda.is_available() ? cuda : cpu
  - rerank: 후보 수 <= top_k 이면 리랭커 생략

4.6 app/llm.py
  - OpenAI 호환 chat/completions (llama-server)
  - think 모드 해석 (resolve_think_mode, /think·/no_think)
  - LLAMA_CPP_MODEL 비어 있으면 payload에 model 키 생략 (서버 기본 모델)
  - LLAMA_CPP_API_KEY 기본 "no-key"
  - instant 실패 시 max_tokens 2배 재시도 1회

4.7 app/ingest.py
  - 진입: ingest_documents(reset=False)
  - main.py: ingest --reset → reset=True
  - progress.py 로 진행률 출력

4.8 app/query.py
  - 진입: ask_question(question, think_mode="auto", history=None) → str
  - web_server, main.py ask 에서 공통 사용
  - CHAT_HISTORY_MAX_MESSAGES 로 LLM에 넣을 이전 메시지 수 제한

4.9 app/chat_db.py — ChatStore
  - 동일 chunks.sqlite3 에 chat_sessions / chat_messages 테이블
  - list/create/get/delete session, add/list messages
  - 웹 UI 멀티턴의 영속 저장소

4.10 app/main.py
  - 서브커맨드: ingest, ask, serve
  - ingest --reset 플래그만 (incremental CLI 플래그 없음)

4.11 app/web_server.py
  - ThreadingHTTPServer
  - GET  /, /static/*              → Vue 채팅 UI
  - GET/POST /api/sessions         → 목록 / 새 대화
  - GET/DELETE /api/sessions/{id}  → 조회 / 삭제
  - POST /api/sessions/{id}/messages → {content, think_mode} → RAG 답변 저장
  - POST /api/ask                  → 레거시 {"question"} → {"answer"} (히스토리 없음)

5. 저장소 스키마
================================================================================

5.1 SQLite — chunks
  id            INTEGER PRIMARY KEY   (FAISS 벡터 인덱스와 동일)
  file_name     TEXT NOT NULL
  source_path   TEXT NOT NULL         (절대 또는 원본 PDF 경로)
  page          INTEGER NULL
  bbox          TEXT NULL             (JSON 배열 문자열)
  element_type  TEXT NULL             (paragraph, table, heading, ...)
  text          TEXT NOT NULL         (청크 본문)
  created_at    TEXT NOT NULL         (ISO8601 UTC)

5.2 SQLite — ingest_manifest
  rel_path      TEXT PRIMARY KEY      (docs/ 기준 상대 경로)
  size          INTEGER               (바이트)
  mtime         REAL                  (st_mtime)

5.3 SQLite — chat_sessions (chat_db.py)
  id            TEXT PRIMARY KEY      (UUID)
  title         TEXT NOT NULL
  created_at    TEXT NOT NULL
  updated_at    TEXT NOT NULL

5.4 SQLite — chat_messages (chat_db.py)
  id            INTEGER PRIMARY KEY AUTOINCREMENT
  session_id    TEXT NOT NULL         → chat_sessions(id) ON DELETE CASCADE
  role          TEXT NOT NULL         (user | assistant)
  content       TEXT NOT NULL
  created_at    TEXT NOT NULL

5.5 FAISS
  - IndexFlatIP (정확 전수 검색, L2 normalize 벡터 → 코사인)
  - 파일: data/index/faiss.index

5.6 meta.json
  {
    "dimension": 1024,
    "embed_model": "BAAI/bge-m3",
    "rerank_model": "BAAI/bge-reranker-v2-m3",
    "count": <청크 수>,
    "updated_at": "<ISO8601>"
  }

7. CLI·웹 API
================================================================================

7.1 CLI
  python app/main.py ingest [--reset]
  python app/main.py ask --question "질문"
  python app/main.py serve [--host H] [--port P]

  ※ app/ 디렉터리가 sys.path[0] 이므로 app/ 내에서 상대 import 동작.
     프로젝트 루트에서 `python app/main.py` 실행 권장.
  ※ Windows: scripts\local-rag.bat [serve|ingest|ask|llama|models]

7.2 웹 API (주력: 세션)
  GET  /api/sessions
    Response: 200 {"sessions": [{id, title, created_at, updated_at}, ...]}

  POST /api/sessions
    Request:  {"title": "새 대화"}  (title 생략 가능)
    Response: 201 {"session": {...}}

  GET  /api/sessions/{id}
    Response: 200 {"session": {...}, "messages": [{id, role, content, ...}, ...]}

  DELETE /api/sessions/{id}
    Response: 200 {"ok": true}

  POST /api/sessions/{id}/messages
    Request:  {"content": "질문", "think_mode": "auto"|"instant"|"think"}
    Response: 200 {
                  "session": {...},
                  "user_message": {...},
                  "assistant_message": {...}
                }

7.3 웹 API (레거시)
  POST /api/ask
    Request:  Content-Type: application/json
              {"question": "string"}
    Response: 200 {"answer": "string"}
    Error:    400 {"error": "..."}
    ※ 세션·히스토리·think_mode 미지원 (단발 질의)

7.4 llama-server (별도 프로세스)
  예: llama-server -m qwen.gguf --port 8080 -c 4096
  엔드포인트: http://localhost:8080/v1/chat/completions
  local-rag.bat serve 시 미실행이면 자동 기동 가능

9. 인제스트 모드 (full / append / skip) — 의사코드
================================================================================

if reset:
    mode = full
elif no pdfs:
    mode = skip
elif store.count() == 0:
    mode = full
elif manifest == current_files_sig:
    mode = skip
elif any_removed or any_changed:
    mode = full
else:  # only new files
    mode = append, targets = new_pdfs_only

full:
    store.reset()
    clear_parsed_cache()
    parse all pdfs → chunk → embed → add_chunks
    update manifest for all

append:
    parse new pdfs only → chunk → embed → add_chunks (id 이어서 증가)
    update manifest for all current files

skip:
    no-op

10. 알려진 제한·확장 포인트
================================================================================

제한
  - PDF만 입력. 스캔 PDF는 OpenDataLoader hybrid/OCR 미연동 (기본 json 모드).
  - FAISS IndexFlatIP: 청크 수 증가 시 검색 O(n). 대규모는 IVF/HNSW 또는 Qdrant 검토.
  - append 모드에서 기존 PDF 수정 시 full 재구축 필요 (FAISS 개별 삭제 미구현).
  - 멀티 프로세스 동시 ingest 미지원.
  - 스트리밍/SSE 미구현 (답변은 완료 후 일괄 반환).
  - 테스트·CI·Docker 없음.

  - pdf_parser: OPENDATALOADER hybrid=docling-fast, OCR 옵션
